HTTP Request 成功，但 n8n 模型节点返回 404

先把工作流缩减为一个可对照的请求，再检查实际 Base URL、准确模型 ID 和 Chat/Responses 设置，不要直接排查复杂的 AI Agent。

更新于 2026-11-27 · 约 8 分钟 · 检查清单不需要工作流凭据
快速结论

HTTP Request 节点使用完整 URL，OpenAI Chat Model 节点则根据凭据、Base URL、模型和 API 选项构造请求。节点级覆盖项或不受支持的 Responses 设置，可能把有效 Key 发往不同路由。

1. 让两个请求具有可比性

修改模型或凭据前，并排比较以下字段：

字段HTTP Request 节点OpenAI Chat Model 节点
URL文档给出的完整聊天路由来自凭据或节点覆盖项的 Base URL
模型JSON 正文中的准确 ID节点选择或输入的准确 ID
凭据Generic Header Auth 或同类方式节点选择的 OpenAI 凭据
操作一次受控的非流式文本请求Chat 或 Responses，以及节点和 Agent 选项

使用 Reply with OK only. 等合成测试消息，不要把生产提示词或客户数据复制到测试工作流。

2. 检查凭据与节点级 Base URL

许多 OpenAI 兼容服务商可以使用以下配置结构：

OpenAI 凭据
  API Key: <AI_API_KEY>
  Base URL: https://provider.example/v1
  Organization ID: 除非服务商要求，否则留空

OpenAI Chat Model
  Model: By ID → exact-public-model-id
  Options → Base URL: 留空以继承凭据
  Use Responses API: 初始 Chat Completions 测试时关闭
  1. 包含服务商要求的 Base URL 片段。通常是 /v1，而不是完整的 /chat/completions 路由。
  2. 检查 Options → Base URL。节点级值可能覆盖凭据，把同一个 Key 发往其他服务商或路径。
  3. 必要时直接输入模型 ID。如果端点不支持 GET /models 或列表不完整，无法从列表选择并不必然代表模型不可用。
n8n 的字段名称和可用选项随版本不同。请以当前安装节点的实际字段为准，不要假定旧截图完全一致。

3. 仅在明确支持时启用 Responses

较新的 n8n 节点可能提供 Use Responses API。该选项会改变 API 协议，不是单纯的显示偏好。

  • 如果服务商只支持 /chat/completions，保持 Responses 关闭。
  • 如果启用，使用相同 Base URL 和准确模型单独验证 /responses。
  • 不要假定支持 OpenAI 风格身份验证或模型列表，就意味着同时支持两种生成 API。

真实对比请求可能产生服务商费用。请先查看价格，每次只发送一个最小请求：

curl "https://provider.example/v1/chat/completions" \
  -H "Authorization: Bearer $AI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"exact-public-model-id","messages":[{"role":"user","content":"Reply with OK only."}],"max_tokens":32,"stream":false}'

4. 先用简单文本链，再测试 AI Agent

最小 HTTP 请求成功后，在简单文本链中使用相同凭据和模型测试模型节点，暂时关闭流式、工具和结构化输出。

  1. 如果简单文本链失败，比较它与 HTTP Request 节点的实际路由和协议。
  2. 如果简单文本链通过而 AI Agent 失败，每次只恢复工具、JSON 输出或流式中的一项。
  3. 同时检查协议支持和模型行为。端点可能接受 tools 字段却返回不同的工具调用结构，也可能只是模型没有选择工具。
普通文本通过不能证明工具调用、流式或结构化输出可用。这些能力需要在目标 n8n 工作流中分别验证。

5. 防止重试放大故障和费用

模型节点的 Max Retries、节点的 Retry On Fail 设置以及服务商或网关都可能执行重试。一次逻辑操作可能因此变成多次尝试。

  • 定位最初故障时，暂时关闭额外重试。
  • 遇到 429，分别检查 RPM、TPM、并发、额度和 Retry-After。
  • 解决根因后只恢复确有需要的重试行为。每次尝试都可能计费。
安全分享：从导出的工作流和截图中删除 API Key、凭据 ID、客户数据、提示词、模型输出和内部主机名。只保留 n8n 版本、节点类型、公开模型 ID、HTTP 状态和脱敏路径结构。

常见问题

为什么 HTTP Request 节点成功，OpenAI Chat Model 节点却返回 404？

HTTP Request 节点使用完整 URL，模型节点则根据凭据、Base URL、模型和 API 选项构造请求。节点覆盖项或 Responses 设置可能生成不同的实际路由。

所有 OpenAI 兼容服务商都应该启用 Use Responses API 吗？

不应该。只有所选服务商和模型支持 /responses 时才启用，否则应先在简单文本链中使用 Chat Completions。

排障时为什么要检查重试设置？

模型节点、工作流设置和网关都可能重试。一次逻辑操作可能变成多个计费请求，也会掩盖最初的故障。
