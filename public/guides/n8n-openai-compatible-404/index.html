HTTP Request works, but the n8n model node returns 404

Reduce the workflow to one comparable request, then check the effective Base URL, exact model ID and Chat/Responses setting before debugging an AI Agent.

Updated 2026-11-27 · 8 minute read · No workflow credentials required for the checklist
Quick answer

The HTTP Request node uses a full URL. The OpenAI Chat Model node builds its request from a credential, Base URL, model and API options. A node-level override or unsupported Responses setting can send an otherwise valid key to a different route.

1. Make the two requests comparable

Before changing the model or credentials, compare these fields side by side:

FieldHTTP Request nodeOpenAI Chat Model node
URLFull documented chat routeBase URL from credential or node override
ModelExact ID in the JSON bodyExact ID selected or entered in the node
CredentialGeneric Header Auth or equivalentSelected OpenAI credential
OperationOne controlled, non-streaming text requestChat or Responses, plus any node and Agent options

Use one synthetic message such as Reply with OK only. Do not copy production prompts or customer data into a test workflow.

2. Check the credential and node-level Base URL

For many OpenAI-compatible providers, the OpenAI credential uses this shape:

OpenAI credential
  API Key: <AI_API_KEY>
  Base URL: https://provider.example/v1
  Organization ID: leave empty unless required

OpenAI Chat Model
  Model: By ID → exact-public-model-id
  Options → Base URL: leave empty to inherit the credential
  Use Responses API: Off for initial Chat Completions testing
  1. Include the provider's required base segment. This is commonly /v1, not the full /chat/completions route.
  2. Check Options → Base URL. A node-level value can override the credential and point the same key at a different provider or path.
  3. Enter the model ID directly when needed. If GET /models is unsupported or the list is incomplete, a list-selection failure does not necessarily mean the model itself is unavailable.
n8n labels and available options vary by version. Check the fields in your installed node rather than assuming an older screenshot is identical.

3. Disable Responses unless it is explicitly supported

Newer n8n nodes may offer Use Responses API. That option changes the API surface; it is not a cosmetic preference.

  • If the provider supports only /chat/completions, leave Responses off.
  • If you enable it, verify /responses separately with the same Base URL and exact model.
  • Do not assume that support for OpenAI-style authentication or model listing implies support for both generation APIs.

A live comparison may incur provider charges. Review pricing and send only one minimal request at a time:

curl "https://provider.example/v1/chat/completions" \
  -H "Authorization: Bearer $AI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"exact-public-model-id","messages":[{"role":"user","content":"Reply with OK only."}],"max_tokens":32,"stream":false}'

4. Test a simple text chain before an AI Agent

Once the minimal HTTP request works, test the same credential and model in a simple text chain with the model node. Temporarily disable streaming, tools and structured output.

  1. If the simple chain fails, compare its effective route and protocol with the HTTP Request node.
  2. If the simple chain passes but an AI Agent fails, reintroduce tools, JSON output and streaming one at a time.
  3. Check both protocol support and model behavior. An endpoint may accept a tools field but return a different tool-call structure, or a model may simply not select the tool.
A plain text pass does not prove tool calling, streaming or structured output. Those capabilities require separate checks in the target n8n workflow.

5. Prevent retries from multiplying the failure

The model node's Max Retries, the node's Retry On Fail setting and a provider or gateway can each retry. One logical operation may therefore become several attempts.

  • Temporarily disable extra retries while isolating the first failure.
  • For 429, inspect RPM, TPM, concurrency, quota and Retry-After separately.
  • Restore only intentional retry behavior after the root cause is fixed. Every attempt may be billable.
Share safely: remove API keys, credential IDs, customer data, prompts, model outputs and internal hostnames from exported workflows and screenshots. Keep only the n8n version, node type, public model ID, HTTP status and redacted route shape.

Common questions

Why can the HTTP Request node work while the OpenAI Chat Model node returns 404?

The HTTP Request node uses a full URL, while the model node constructs a request from its credential, Base URL, model and API options. A node override or Responses setting can produce a different effective route.

Should I enable Use Responses API for every OpenAI-compatible provider?

No. Enable it only when the selected provider and model support /responses. Otherwise start with Chat Completions in a simple text chain.

Why should retries be reviewed during diagnosis?

The model node, workflow settings and a gateway can each retry. One logical operation may become several billable attempts and obscure the original failure.
